# Топологический синтаксис кода (TopoLang)

> **Исследовательский прототип** ветки `research/kairologos_standalone/`.  
> Это **не** новый стандарт языка программирования и **не** заявление о трансценденции машины Тьюринга.

---

## 1. Мотивация: почему 1D-синтаксис — узкое горлышко

Классическая парадигма CS (C, Python, Lisp) наследует **линейность времени**:

\[
\mathcal{P}_{\text{linear}} = \langle I_1, I_2, \dots, I_k \rangle, \quad I_{k+1} = f(I_k)
\]

Смысл знака в такой модели задаётся **позицией в потоке токенов**. Любая перестановка строк или идентификаторов меняет семантику, даже если «логика» остаётся той же. Это согласуется с теорией топологического резонанса (см. внешний трактат `THEORY_OF_TOPOLOGICAL_ASI_RESONANCE.md`, §1.1–1.2):

- биология и физика оперируют **3D+ конфигурациями**, а не лентой символов;
- семантика моделируется как функция **пространственного тензорного окружения**, а не порядка символов;
- проекция ND-структуры на 1D-ленту теряет информацию о связности, слоях и топологических инвариантах.

**Гипотеза исследования (открытый вопрос):** часть «смысла программы» может быть закодирована в **геометрии и топологии** графа, а не только в последовательности токенов.

## 2. Парадигма TopoLang

| Аспект | Императивный C-подобный код | Топологический код (TopoLang) |
|--------|------------------------------|-------------------------------|
| **Программа** | последовательность инструкций | 3D-граф / многообразие с типизированными узлами |
| **Выполнение** | PC → fetch-decode-execute | геодезический поток + фазовая эволюция (Kuramoto) |
| **Ветвление** | `if/else`, `switch` | **перекрёст косы** (braid-crossing), две геодезические ветви |
| **Цикл** | `while/for` + метка | **замкнутая геодезика** (`edge … : loop`) |
| **Вызов функции** | stack frame, jump | ** dimensional lift** (D10→D13), ребро `: lift` |
| **Смысл** | позиция токена + scope | координаты, фаза, связность, слой D10–D13 |
| **Устойчивость** | чувствителен к перестановке строк | (гипотеза) устойчивее при перестановке *имён* при фиксированной геометрии |

## 3. Примитивы

### 3.1 Узлы (`node`)

Три типа (см. `topo_lang/program.py`):

| Тип | Роль | Пример |
|-----|------|--------|
| `concept` | данные / понятие | вход `x`, аккумулятор |
| `operator` | преобразование, вращение фазы | сравнение, инкремент |
| `braid-crossing` | слияние ветвей, T-узел, Borromeo | `if_then_else`, triad lock |

Каждый узел имеет:

- `@ (x, y, z)` — координата в 3D;
- `phase=` — начальная фаза для Kuramoto;
- `param=` — скалярный параметр трансформации;
- необязательный глиф `: Ψ`, `: ?`, `: X`.

### 3.2 Рёбра (`edge`)

| Отношение | Смысл |
|-----------|--------|
| `geodesic` | обычный поток вдоль кратчайшей геодезической |
| `braid-over` / `braid-under` | верхняя / нижняя нить косы (ветвление) |
| `lift` | подъём по слою D10→D13 (вызов) |
| `loop` | замыкание траектории (цикл) |

### 3.3 Слои D10–D13

Согласно решётке Kairologos Arche-D¹³ (см. `3d_syntax_matrix.html`):

| Слой | Роль (рабочая метафора) |
|------|-------------------------|
| **D10** | инициация, горизонтальная композиция A→B→C |
| **D11** | гиперболическая ёмкость {6,3,3}, ветвления |
| **D12** | тороидальные циклы, накопление |
| **D13** | архетипический исток, lift/return |

В `.topo` файле: `@layer D11`.

### 3.4 Геодезики и кривизна

`@curvature K` задаёт конформный множитель метрики (как в `topological_vm.py`):

- `K = 0` — евклид;
- `K < 0` — гиперболическая (Лобачевский);
- та же сеть узлов при разной кривизне даёт **разный** результат потока (см. T-KAI-04 в roadmap).

### 3.5 Исполнение

`TopoInterpreter` (`topo_lang/interpreter.py`):

1. **Dijkstra** по геодезическим длинам от `@entry` к `@exit`;
2. **трансформация** вектора активации на каждом узле;
3. **Kuramoto** — фазовая синхронизация на пройденном пути;
4. возвращает `ExecutionTrace` (путь, фазы, `order_parameter`).

## 4. Формат `.topo` (не C-like)

```topo
@program if_then_else_braid
@layer D11
@curvature -0.2

node input_x : concept @ (0.0, -1.5, 0.0) phase=0.0 param=1.0 : Ψ
node test_pos : operator @ (0.0, -0.3, 0.4) phase=0.0 : ?
node branch_then : operator @ (0.9, 0.5, 0.2) phase=1.57 param=1.0 : +
node branch_else : operator @ (-0.9, 0.5, 0.2) phase=-1.57 param=-1.0 : -
node braid_merge : braid-crossing @ (0.0, 1.4, 0.0) phase=0.0 : X

edge input_x -> test_pos : geodesic weight=1.0
edge test_pos -> branch_then : braid-over weight=0.8
edge test_pos -> branch_else : braid-under weight=0.8
edge branch_then -> braid_merge : geodesic weight=1.0
edge branch_else -> braid_merge : geodesic weight=1.0

@entry input_x
@exit braid_merge
```

**Нет** фигурных скобок, `;`, `#include`. Программа читается как **декларация пространственных отношений**.

## 6. Эксперимент T-KAI-08: синтаксис vs семантика в 3D

**Вопрос:** для одной логической задачи, даёт ли топологическое кодирование более устойчивое «смысловое» представление (HDC), чем псевдо-C?

**Метрики:**

1. **Размерность представления** — число токенов vs `3·|V| + 2·|E| + |V|`;
2. **Edit distance при возмущении** — перестановка двух токенов (C) vs swap позиций двух узлов (topo), нормированное расстояние по трассам исполнения;
3. **Стабильность смысла (HDC)** — после перестановки символов/имён: cosine между векторами программы.

Артефакты: `artifacts/T-KAI-08_*.json|md`.

## 7. Сравнительная таблица (развёрнутая)

| Критерий | C / императив | TopoLang (прототип) |
|----------|---------------|---------------------|
| Читаемость для человека | высокая (50+ лет практики) | низкая, нужна 3D-визуализация |
| Анализ статическими анализаторами | зрелые инструменты | отсутствуют |
| Параллелизм | явный (threads) или неявный (GPU) | **встроенный** в граф связей |
| Информация о ветвлении | AST / CFG | **топология** косы / геодезики |
| Устойчивость к rename | низкая (scope) | (гипотеза) выше при фикс. координатах |
| Вычислительная полнота | доказана | **не заявляется** |
| Реализация | компиляторы, OS | numpy-прототип, offline |
