# Contributing

Use one milestone or falsifiable hypothesis per pull request.

Required:

- an issue describing the behavioral claim;
- tests including an abstain or denial case;
- make check passes;
- no unreviewed change to hard constraints;
- documentation of new data, capability or threat;
- exact experiment config and seed for performance claims.

Avoid:

- hidden state only present in prompts;
- model-generated policy;
- benchmark tuning without held-out scenarios;
- metrics based only on message frequency or engagement;
- anthropomorphic interpretation of drive variables.
